# FEELCONOMY LAB 웹사이트 개발 요청

나는 고등학교 GBL 게이미피케이션 부스에서 사용할 **FEELCONOMY LAB: 감정 기반 소비 잠재수요 분석 웹사이트**를 제작하려고 한다.

이 웹사이트는 단순한 성격 테스트나 소비 추천 사이트가 아니다.

참가자가 자신의 현재 감정을 수치화하고, 사전에 구축된 집단 감정 데이터와 SVD 및 K-means 분석 결과를 이용하여 자신의 감정 패턴이 어느 소비집단과 가까운지를 확인하며, 그 집단에서 나타난 소비성향을 자신의 잠재 소비 방향으로 해석하는 **교육용 데이터 분석 체험 시스템**이다.

웹사이트를 구현하기 전에 아래의 연구 목적, 수학적 구조, 데이터 처리 규칙, 사용자 흐름을 반드시 이해하고 그 구조에 맞게 설계해라.

---

# 1. 프로젝트의 핵심 목적

전체 활동의 기본 흐름은 다음과 같다.

**감정 수치화**
→ **집단 감정 데이터 분석**
→ **SVD를 이용한 차원축소**
→ **K-means를 이용한 유사 감정집단 형성**
→ **각 집단의 실제 소비성향 분석**
→ **새로운 참가자를 가장 가까운 집단에 배정**
→ **해당 집단의 소비성향을 개인의 잠재 소비 방향으로 제시**

참가자에게

> "당신은 반드시 다음에 여행을 소비할 것입니다."

처럼 단정적인 예측을 제공해서는 안 된다.

대신

> "현재 당신과 유사한 감정 패턴을 가진 집단에서는 여행·문화·취미 소비성향이 상대적으로 높게 나타났습니다."

와 같이 **집단 데이터 기반의 확률적·탐색적 결과**로 표현해야 한다.

---

# 2. 기존 방식에서 변경된 점

기존 계획에서는 감정 몇 개를 평가한 뒤 별도로 정의한 S값과 R값을 계산하고, R값의 범위를 기준으로 소비유형을 결정하는 방식이었다.

이 방식은 사용하지 않는다.

새로운 시스템에서는 참가자의 감정을 보다 세밀하게 10개 변수로 구성하고, 실제 집단 데이터를 기반으로 SVD와 K-means를 사용한다.

따라서 다음 요소는 사용하지 않는다.

* S값
* R값
* R ≥ 1.1 등의 임의 군집 기준
* 감정점수 몇 개를 단순 합산하여 소비유형을 결정하는 방식
* 사람이 임의로 미리 지정한 군집 중심

---

# 3. 감정 데이터 구조

기본적으로 한 참가자는 **10개의 감정변수**에 대해 각각 1~10점의 점수를 입력한다.

현재 감정 변수의 구체적인 명칭은 추후 변경 가능하도록 별도 설정 파일로 관리한다.

예시:

1. 기쁨
2. 설렘
3. 활력
4. 여유
5. 안정감
6. 스트레스
7. 피로
8. 허전함
9. 충동성
10. 호기심

한 참가자의 데이터는 다음과 같은 10차원 벡터가 된다.

`x = [8, 7, 9, 3, 4, 2, 3, 1, 7, 9]`

여러 사람의 데이터가 모이면

`N명 × 10개 감정변수`

형태의 데이터 행렬 X가 만들어진다.

감정 변수의 개수와 이름은 코드에 하드코딩하지 말고 설정값으로 분리하여 나중에 쉽게 수정할 수 있게 만들어라.

---

# 4. 소비 데이터

감정정보와 별개로 소비정보도 수집한다.

소비 카테고리는 추후 수정 가능하도록 설정 파일에서 관리한다.

예시:

* 카페·디저트
* 외식
* 뷰티
* 패션
* 도서
* 여행
* 공연·문화
* 게임
* 운동
* 취미
* 생활용품
* 자기계발

참가자에게 최소한 다음 두 종류를 받을 수 있도록 구조화한다.

### 최근 소비

최근 자신이 자주 선택한 소비 카테고리

### 희망 소비

앞으로 하고 싶거나 관심 있는 소비 카테고리

복수 선택 여부는 설정으로 변경할 수 있도록 한다.

이 소비정보는 SVD 자체의 입력변수로 사용하지 않는 것을 기본 원칙으로 한다.

SVD와 K-means는 우선 감정 패턴을 이용해 사람들을 분석하고, 소비데이터는 이후 각 군집의 소비특성을 해석하기 위해 사용한다.

---

# 5. 가장 중요한 데이터 구분

웹사이트에서는 데이터를 반드시 다음 두 종류로 분리한다.

## A. 기준 데이터셋 Reference Dataset

행사 전에 내가 별도로 준비하여 제공할 데이터다.

이 데이터로

* 감정별 평균
* SVD 잠재축
* 설명분산
* 저차원 좌표
* K-means 군집
* 군집 중심
* 군집별 소비성향

등을 계산한다.

이 데이터셋의 구체적인 내용은 내가 추후 직접 채울 것이므로 지금 임의의 실제 데이터를 만들어 연구 결과처럼 사용하지 마라.

개발을 위해 필요한 경우에만 `sample_reference.csv`와 같은 명확한 **가상 테스트 데이터**를 별도로 만들고 실제 연구데이터와 구분한다.

---

## B. 행사 참가자 데이터 Participant Dataset

웹사이트를 사용하는 참가자가 행사 당일 입력하는 데이터다.

참가자의

* 익명 ID
* 감정 10개 점수
* 최근 소비
* 희망 소비
* 입력 시각
* 계산된 잠재좌표
* 배정된 군집
* 군집까지의 거리

등을 저장한다.

이 데이터는 새로운 연구자료로 축적한다.

---

# 6. 절대 지켜야 할 모델 운영 규칙

**행사 도중 참가자 데이터가 추가될 때마다 SVD와 K-means를 다시 학습하지 않는다.**

행사 시작 전에 Reference Dataset으로 모델을 한 번 구축하고 해당 모델을 **고정 Model Version**으로 사용한다.

예:

`model_version = feelconomy_v1`

행사 첫 번째 참가자와 마지막 참가자가 반드시 같은 기준으로 분석되어야 한다.

행사 중 새롭게 들어온 참가자 데이터는 Participant Dataset에 계속 누적하여 저장하되 현재 모델의

* 평균 벡터
* SVD 축
* K-means 중심

을 변경해서는 안 된다.

행사가 끝난 뒤 관리자가 원할 경우에만 새 참가자 데이터를 포함하여 새로운 모델 버전을 재학습할 수 있도록 구조를 분리한다.

---

# 7. SVD 처리 과정

Reference Dataset의 감정 데이터 행렬을 X라고 한다.

먼저 각 감정변수별 평균을 계산한다.

`m = [m1, m2, ..., m10]`

그리고 중심화한다.

`Xc = X - m`

그다음 SVD를 수행한다.

`Xc = U Σ Vᵀ`

각 특이값의 제곱을 이용해 설명분산 비율과 누적 설명분산 비율을 계산한다.

기본 MVP에서는 첫 번째와 두 번째 잠재축을 사용하여 2차원 공간을 구성한다.

단, 코드 구조상 추후 r값을 2, 3 등으로 변경할 수 있게 한다.

첫 두 잠재축을

`V_r = [v1, v2]`

라고 할 때 Reference Dataset의 저차원 좌표는

`Z = Xc × V_r`

로 계산한다.

각 참가자는 10차원 감정벡터에서 2차원 잠재좌표로 변환된다.

---

# 8. 새로운 참가자의 SVD 적용

새로운 참가자의 감정벡터를 x라고 한다.

중요:

새로운 참가자의 평균을 새로 계산하면 안 된다.

기준 데이터셋에서 계산한 기존 평균 m을 그대로 사용한다.

`xc = x - m`

그리고 기존 Reference Dataset에서 구한 동일한 SVD 축을 사용한다.

`z = xc × V_r`

그 결과

`z = [z1, z2]`

라는 참가자 개인의 2차원 잠재좌표가 생성된다.

---

# 9. K-means 처리 과정

Reference Dataset의 잠재좌표 Z를 이용하여 K-means를 수행한다.

초기화는 일반 무작위 초기화보다 **k-means++**를 사용한다.

초기값 의존성을 줄이기 위해 여러 차례 초기화를 수행하고 가장 낮은 WCSS 값을 가진 결과를 선택하도록 구현한다.

기본 권장:

`n_init = 50`

K값은 코드에 완전히 고정하지 말고 설정 가능하도록 한다.

K=2, 3, 4, 5 등을 비교할 수 있어야 하며 추후 내가 실제 데이터 분석 후 최종 K를 결정할 예정이다.

가능하다면 관리자 분석 화면에서 각 K에 대해 다음을 확인할 수 있도록 한다.

* WCSS
* 평균 silhouette score
* 각 군집 인원수

하지만 부스 참가자 화면에는 이런 복잡한 통계치를 노출할 필요가 없다.

---

# 10. 새로운 참가자의 군집 결정

새로운 참가자의 잠재좌표가

`z = [z1, z2]`

이고 기존 K-means 군집 중심이

`μ1, μ2, ..., μK`

라면 각 중심까지의 제곱 유클리드 거리를 계산한다.

`Dk² = ||z - μk||²`

가장 거리가 작은 군집을 해당 참가자의 **가장 가까운 유사 감정집단**으로 결정한다.

표현상

"당신은 무조건 ○○형이다"

보다

"현재 감정 패턴이 ○○ 집단과 가장 가까운 것으로 나타났습니다."

라고 표시한다.

---

# 11. 군집의 소비특성 분석

각 군집이 형성된 뒤 Reference Dataset에 포함된 실제 소비정보를 이용해 각 군집의 소비 카테고리 분포를 계산한다.

예:

군집 1

* 공연·문화 34%
* 여행 28%
* 취미 21%
* 카페·디저트 10%
* 기타 7%

이와 같이 군집별 소비특성을 계산한다.

이후 연구자가 해당 군집을 해석하여 이름을 붙일 수 있다.

예:

* 경험확장형
* 정서회복형
* 실용안정형

중요:

K-means가 자동으로 이러한 이름을 생성한 것처럼 처리하지 않는다.

먼저 군집을 수학적으로 형성한 뒤, 감정 특성과 소비특성을 분석하여 연구자가 군집 이름을 지정하는 구조다.

군집명은 관리자 페이지에서 자유롭게 변경할 수 있도록 한다.

---

# 12. 잠재수요 결과 표현

참가자가 특정 군집에 배정되었다면 해당 군집의 소비성향을 보여준다.

예시 UI:

### 나와 가장 가까운 감정집단

경험확장형

### 현재 나의 잠재좌표

축 1: 2.63
축 2: -0.84

### 이 집단에서 많이 나타난 소비방향

1. 공연·문화 34%
2. 여행 28%
3. 취미 21%

### 결과 해석

"현재 당신의 감정 패턴은 경험확장형 집단과 가장 가까웠습니다. 기준 데이터에서 이 집단은 공연·문화, 여행, 취미와 같은 경험 중심 소비를 상대적으로 많이 선택했습니다."

다음과 같은 문구는 피한다.

* "당신은 여행을 살 것입니다."
* "당신의 소비는 여행입니다."
* "AI가 당신의 다음 구매를 정확히 예측했습니다."

이 시스템의 결과는 **집단패턴을 이용한 잠재 소비 방향 추정**이라는 점을 유지한다.

---

# 13. 교육용 웹사이트라는 점이 중요하다

이 웹사이트의 핵심은 단순히 입력 후 결과를 보여주는 것이 아니다.

참가자가

**10개의 감정정보가 어떻게 수학적 계산을 거쳐 2개의 좌표로 줄어들고, 그 좌표가 어떻게 군집 판정으로 이어지는지**

이해할 수 있어야 한다.

따라서 결과 과정에서 다음 흐름을 시각적으로 보여준다.

`감정벡터`
↓
`평균 제거`
↓
`SVD 잠재축과 내적`
↓
`2차원 잠재좌표`
↓
`군집 중심과 거리 비교`
↓
`가장 가까운 집단`
↓
`그 집단의 소비특성`
↓
`잠재수요 방향`

단, 중학생도 이해할 수 있도록 설명한다.

예:

SVD
→ "10개의 복잡한 감정정보를 중요한 2개의 특징으로 압축합니다."

K-means
→ "비슷한 위치에 있는 사람들을 하나의 그룹으로 묶습니다."

내적
→ "내 감정점수와 잠재축의 숫자를 각각 곱한 뒤 모두 더합니다."

---

# 14. 종이 학습지와 웹사이트의 관계

향후 참가자에게 별도의 계산 학습지를 제공할 예정이다.

학습지에서는 참가자가 직접

1. 자신의 감정점수 확인
2. 기준 평균 빼기
3. SVD 계수와 일부 내적 계산
4. 자신의 잠재좌표 계산
5. 군집 중심과 거리 비교

등을 체험한다.

웹사이트는 동시에 동일한 계산을 자동으로 수행한다.

따라서 결과 화면에는 향후

**내 손계산 결과 입력**

기능을 추가할 수 있게 설계한다.

예:

내가 계산한 z1 = ___
내가 계산한 z2 = ___

프로그램 계산:

z1 = 2.63
z2 = -0.84

오차:

Δz1 = ...
Δz2 = ...

이를 통해

"내가 컴퓨터의 계산과정을 얼마나 정확하게 따라 했는가?"

도 하나의 게임 요소가 될 수 있다.

MVP에서 구현이 부담된다면 이 기능은 별도 컴포넌트로 분리하고 나중에 활성화할 수 있도록 한다.

**"오늘 내 감정이 소비와 연결된다면?"**

간단한 설명:

"10개의 감정점수를 데이터로 바꾸고, 나와 비슷한 감정집단에서 어떤 소비가 나타나는지 직접 분석해보세요."

시작 버튼

---

## 페이지 2. 익명 참여 안내

* 개인 이름을 필수로 받지 않는다.
* 자동으로 Participant ID 생성
* 입력 데이터가 탐구 분석에 사용된다는 안내
* 동의 후 진행

---

## 페이지 3. 현재 감정 입력

10개 감정 각각을 1~10 범위로 입력한다.

모바일에서도 쉽게 누를 수 있도록 슬라이더보다 **1~10 숫자 버튼** 또는 큰 선택 UI를 우선 검토한다.

각 감정에는 짧은 설명 또는 도움말을 둘 수 있다.

모든 문항을 입력해야 다음 단계로 넘어간다.

---

## 페이지 4. 소비정보 입력

최근 소비 카테고리 선택

앞으로 관심 있거나 하고 싶은 소비 카테고리 선택

다음 버튼

---

## 페이지 5. 데이터 변환 과정

참가자의 원본 감정벡터를 보여준다.

예:

`[8, 7, 9, 3, 4, 2, 3, 1, 7, 9]`

그리고

"사람마다 감정을 높게 또는 낮게 평가하는 기준이 다르기 때문에 먼저 기준 집단의 평균과 비교합니다."

라고 설명한다.

중심화 결과를 시각적으로 보여준다.

---

## 페이지 6. SVD 체험

"10개의 감정정보를 중요한 2개의 특징으로 압축합니다."

SVD 결과로 나온 z1, z2를 보여준다.

가능하면 간단한 애니메이션이나 단계 표시를 사용한다.

수식은 필요할 때 펼쳐서 볼 수 있도록 한다.

기본 화면은 중학생도 이해할 수 있는 설명을 우선한다.

---

## 페이지 7. 잠재공간 지도

2차원 scatter plot을 표시한다.

* Reference Dataset 참가자 점
* 각 K-means 군집
* 각 군집 중심
* 현재 참가자 위치

를 표시한다.

개인정보가 드러나지 않도록 다른 참가자의 이름이나 ID는 표시하지 않는다.

현재 참가자의 위치는 눈에 띄게 구분한다.

군집은 색상뿐 아니라 번호나 도형 등으로도 구분할 수 있도록 접근성을 고려한다.

---

## 페이지 8. K-means 판정 과정

각 군집 중심과 자신의 거리를 보여준다.

예:

군집 A: 0.42
군집 B: 3.81
군집 C: 5.17

그리고

"가장 가까운 중심을 가진 집단을 찾습니다."

라고 설명한다.

---

## 페이지 9. 최종 결과

* 가장 가까운 군집명
* 잠재좌표
* 대표 감정 특성
* 군집 소비 카테고리 순위
* 잠재수요 해석
* 자신이 입력한 희망소비와의 비교

등을 카드 형태로 보여준다.

---

## 페이지 10. 마무리

짧은 교육적 정리:

"당신의 10개 감정은 하나의 벡터가 되었고, SVD로 2개의 잠재특징으로 압축되었습니다. 이후 K-means 군집과의 거리를 비교하여 가장 비슷한 집단을 찾았습니다."

처음으로 돌아가기 버튼

다음 참가자가 사용할 경우 이전 참가자 정보가 화면에 남지 않도록 세션 초기화 버튼을 제공한다.

---

# 16. 관리자 페이지

일반 참가자가 접근하기 어려운 별도 관리자 페이지를 만든다.

필요 기능:

### Reference Dataset 관리

* CSV 업로드
* 데이터 컬럼 검증
* 행 수 확인
* 결측값 확인
* 잘못된 1~10 범위 값 검사
* 데이터 미리보기

### 모델 구축

* 평균 계산
* SVD 실행
* 특이값 확인
* 설명분산 확인
* 사용할 차원 r 선택
* K 설정
* K-means++ 실행
* 여러 초기화 결과 중 최소 WCSS 결과 채택

### 군집 분석

* 군집 인원수
* 군집 중심
* 감정 평균
* 소비 카테고리 분포
* 군집명 직접 입력

### Model Version

모델을 저장할 때 버전을 부여한다.

예:

`FEELCONOMY-V1`

행사 중에는 해당 버전을 잠근다.

관리자가 명시적으로 새 모델을 생성하기 전에는 자동 재학습하지 않는다.

### Participant Dataset

행사 참가자 데이터 조회

* 익명 ID
* 입력시각
* 감정점수
* 소비선택
* z 좌표
* 배정 군집
* 사용된 model version

CSV 다운로드 기능 제공

# 17. 데이터 저장 규칙

최소한 다음 구조를 고려한다.

## Reference record

* id
* emotion_1 ~ emotion_10
* recent_consumption
* desired_consumption

## Participant record

* participant_id
* created_at
* emotion values
* recent consumption
* desired consumption
* centered vector
* z1
* z2
* assigned_cluster
* distance_to_each_cluster
* model_version

중심화 벡터 전체를 DB에 저장할 필요가 없다면 계산 로그와 원자료만 저장해도 좋다.

하지만 재현성을 위해

* 입력 원자료
* 사용된 모델 버전
* 결과 좌표
* 군집 결과

는 반드시 저장한다.

---

# 18. 데이터 개인정보 원칙

학생 대상 활동이므로 개인정보를 최소화한다.

기본적으로

* 이름
* 전화번호
* 이메일
* 학번

을 수집하지 않는다.

자동 생성 익명 ID를 사용한다.

예:

`P-20260814-001`

관리자 화면에서도 참가자 개인을 특정할 수 있는 정보를 기본적으로 두지 않는다.

# 19. 기술 구현 방향

우선 유지보수성과 이해하기 쉬운 코드를 우선한다.

권장 기술 스택:

* TypeScript
* React 기반 프레임워크
* Tailwind CSS 또는 유사한 간단한 UI 시스템
* 그래프는 Recharts 또는 적합한 시각화 라이브러리
* SVD는 검증된 행렬 연산 라이브러리 사용
* K-means는 k-means++ 초기화가 가능한 라이브러리를 사용하거나 알고리즘을 명확하게 구현

수학 계산을 UI 컴포넌트 내부에 직접 섞지 말고 별도의 모듈로 분리한다.

예:

`lib/math/centering.ts`

`lib/math/svd.ts`

`lib/math/kmeans.ts`

`lib/math/inference.ts`

등과 같이 역할을 분리한다.

UI와 연구 계산 로직을 확실하게 분리한다.

# 20. 저장 방식

먼저 로컬에서 바로 실행 가능한 MVP를 만들어라.

데이터 저장 로직은 추후 Supabase 등의 중앙 데이터베이스로 변경할 가능성이 있으므로 storage layer를 분리한다.

예:

`ParticipantRepository`

`ReferenceDatasetRepository`

등의 인터페이스를 두고

* local implementation
* database implementation

을 교체할 수 있도록 한다.

여러 기기의 참가자가 동시에 접속하는 실제 운영에서는 중앙 DB가 필요하므로 구조적으로 이를 고려한다.

단, 외부 서비스의 API Key가 없어도 개발 및 테스트가 가능한 상태를 우선 만든다.

# 21. 디자인 방향

전체적으로

* 연구소

**"학생이 데이터 분석가가 되어 자신의 데이터를 직접 분석한다"**

는 경험을 중심으로 한다.

# 26. 코드 품질 규칙

* 모든 주요 함수에 역할을 설명하는 주석 작성
* 숫자를 의미 없이 하드코딩하지 않는다.
* 감정변수, 소비카테고리, K값, r값은 config로 관리한다.
* 수학 로직과 UI 로직을 분리한다.
* 입력값 validation을 반드시 한다.
* 1~10 범위를 벗어난 감정점수를 허용하지 않는다.
* 데이터가 부족하거나 모델이 구축되지 않은 경우 가짜 결과 대신 명확한 오류 상태를 보여준다.
* Reference Model이 없으면 참가자에게 군집 결과를 생성하지 않는다.
* 모든 participant result에는 사용된 model version을 기록한다.
* 수학 함수에 간단한 unit test를 작성한다.
* 동일한 입력과 동일한 model version에는 동일한 inference 결과가 나와야 한다.

# 27. 최종적으로 사용자가 경험해야 하는 것

이 웹사이트를 사용한 중학생 또는 고등학생이 활동을 마친 뒤 다음 과정을 설명할 수 있어야 한다.

> "내가 감정을 숫자로 입력하면 하나의 벡터가 된다. 여러 사람의 데이터를 이용해 중요한 감정 변화 방향을 찾을 수 있고, 내 데이터도 그 방향으로 압축할 수 있다. 압축된 공간에서 나와 가까운 사람들의 집단을 찾고, 그 사람들이 실제로 선택한 소비를 확인하면 나에게 나타날 가능성이 있는 소비방향을 추정할 수 있다."

이 교육적 이해가 웹사이트의 가장 중요한 성공 기준이다.
