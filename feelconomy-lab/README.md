# FEELCONOMY LAB

**개인별 소비-감성 잠재수요 분석 웹사이트** — 대천대신고등학교 오량진 GBL 게이미피케이션 부스용 교육 데이터 분석 체험 시스템

참가자가 지금 자신이 원하는 것(감성욕구 6개)과, 여러 소비대안이 그 욕구를 얼마나 채워줄지 평가하면, **참가자 한 명의 데이터만으로** 그 자리에서 SVD와 K-means 분석이 완결됩니다. 다른 참가자의 데이터도, 사전에 준비된 기준 데이터셋도 필요 없습니다.

욕구를 입력하자마자 **MBTI 같은 고정 유형("필코노미 유형", 8종)**을 먼저 공개해 참가자가 오래 기억할 수 있는 정체성을 준 뒤, 소비대안 평가로 이어지는 데이터 분석(SVD/K-means)이 그 정체성과 어떻게 연결되는지 결과 화면에서 함께 보여줍니다. 자세한 설명: [`docs/05_필코노미_유형표.md`](docs/05_필코노미_유형표.md)

## 이 웹사이트가 하는 일

```
현재 감성욕구 6개 입력
        ↓
필코노미 유형(8종 중 하나) 공개 — MBTI 같은 고정 정체성
        ↓
소비대안 8개가 각 욕구를 얼마나 채우는지 평가 (8×6 행렬)
        ↓
SVD로 그 행렬을 압축 — 내가 소비를 판단하는 진짜 기준(잠재축)을 찾는다
        ↓
소비대안 8개와 현재 욕구를 같은 잠재공간에 투영
        ↓
K-means로 소비대안들을 몇 개의 군집으로 묶고 즉석 이름을 붙인다
        ↓
현재 욕구점에서 가장 가까운 군집 = 잠재수요 유형
        ↓
그 군집 안에서 가장 가까운 소비대안 = 세부 잠재수요
```

이 계산은 참가자 한 명의 입력만으로 완결됩니다. 다른 참가자의 데이터도, 사전에 준비된 기준 데이터셋도 필요 없습니다.

## 핵심 설계 원칙

1. **참가자 1명으로 완결**: 기준 데이터셋이나 사전 학습된 모델이 없습니다. 첫 번째 참가자도 자기 데이터만으로 SVD와 K-means를 끝까지 계산합니다.
2. **탐색적 표현**: "당신은 ○○를 살 것입니다" 같은 확정적 문구를 쓰지 않습니다. "지금 욕구가 ○○ 군집과 가장 가까운 것으로 나타났습니다"로 표현합니다.
3. **군집 이름 생성 규칙의 투명성**: 군집 이름은 그 군집 소비대안들의 평균 욕구 점수를 요약한 것이며, 이 규칙을 결과 화면에서 참가자에게 그대로 설명합니다.
4. **개인정보 최소화**: 이름·전화번호·이메일·학번을 수집하지 않습니다. `P-YYYYMMDD-NNN` 형식의 익명 ID만 사용합니다.
5. **재현성**: 시드 고정 난수, SVD 부호 규약, 군집 번호 정규화로 "같은 입력 + 같은 옵션 → 같은 결과"를 보장합니다 (단위 테스트로 검증).
6. **기억에 남는 정체성**: 데이터 분석과 별개로, 감성욕구만으로 결정되는 고정된 8유형("필코노미 유형")을 욕구 입력 직후 먼저 공개합니다. MBTI처럼 이름·태그라인이 있는 정체성을 주되, "성격을 완전히 규정하지 않는다"는 점을 항상 함께 안내합니다.

전체 대응표: [`docs/00_요구사항_요약.md`](docs/00_요구사항_요약.md)

## 관리자 화면

행사 전 준비할 것이 없습니다 — 사전 데이터 업로드나 모델 학습 절차가 없습니다.

- **분석 규격 탭**: 지금 코드에 고정된 감성욕구 축·소비대안·K/r 기본값을 확인합니다 (설정 파일을 고치지 않는 한 실행할 것은 없습니다).
- **참가자 데이터 탭**: 행사 중 쌓인 참가자 기록을 조회하고 CSV로 내보냅니다.

축이나 소비대안 구성을 바꾸려면 `src/config/needs.ts`, `src/config/alternatives.ts`를 수정한 뒤 다시 배포하세요.

## 기술 스택

- TypeScript + React 18 + React Router
- Tailwind CSS v4
- Vitest (수학 모듈 단위 테스트)
- SVD: 직접 구현한 Jacobi 고유분해 (결정론적, 재현 가능)
- K-means: 직접 구현한 k-means++ (WCSS 최소 채택)
- 시각화: 커스텀 SVG (외부 차트 라이브러리 의존성 없음)
- 저장소: localStorage (인터페이스로 추상화되어 있어 중앙 DB로 교체 가능)

외부 API Key 없이 완전히 로컬에서 개발·실행됩니다.
