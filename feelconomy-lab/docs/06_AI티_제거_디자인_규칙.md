## 1. AI Slop이란 무엇인가

AI Slop은 AI가 만든 티가 나는 디자인이다. 판별 근거는 취향이 아니라 **반복되는 지문(fingerprint)**이다.

가장 강한 단일 지문은 **보라-파랑 그라디언트**다. 그 다음이 순수 `#000000` 배경, 3등분 카드 열, 과포화 강조색이다.

핵심 원리는 윤문 스킬과 같다 — **빼기 전용**이다. 화려하게 더하는 것이 아니라, 기계적 균일함을 걷어내면 자연스러운 것이 남는다.

## 2. 지문 목록 (판정 기준)

### 색·표면

- 보라/파랑 그라디언트 → 중립 바탕 + 고려된 강조색 하나
- `#000000` → `#0a0a0a`, `#09090b` 같은 색조 있는 검정
- 채도 80% 초과 강조색 → 낮춘다
- 경쟁하는 강조색 여러 개 → 하나만 남긴다
- `rgba(0,0,0,0.3)` 그림자 → 배경 색조를 띤 그림자
- 질감 0의 완전 평면 → 미세 그레인, 메시 그라디언트
- 밝은 페이지 중간의 갑작스러운 다크 섹션 → 톤 유지, 명도만 변주

### 타이포그래피

- 브라우저 기본 폰트 / Inter / Noto Sans KR → Pretendard
- 한글에 `word-break: keep-all` 누락 → 어절 중간에서 줄이 끊긴다
- 제목 고아 단어 → `text-wrap: balance`
- Regular·Bold만 사용 → Medium(500)·SemiBold(600)로 위계 확보
- 수치가 가변폭 → `tabular-nums` 또는 monospace
- 본문 폭 과다 → 65자 내외로 제한

### 레이아웃

- 전부 중앙 정렬 대칭 → 오프셋, 분할 화면으로 대칭을 깬다
- **3등분 카드 열** → Bento 그리드, 지그재그, 가로 스크롤
- 인접 섹션이 같은 레이아웃 → 반드시 다른 패턴을 쓴다
- `height: 100vh` → `min-height: 100dvh` (iOS Safari)
- 여백 부족 → 섹션 패딩을 두 배로

### 모션

- hover 상태 없음 → `hover:scale-[1.02]`, 배경 전환
- 눌림 피드백 없음 → `active:scale-[0.98]`
- 즉시 전환 → `transition-all duration-300 ease-out`
- 기계적 이징 → 스프링 `cubic-bezier(0.16, 1, 0.3, 1)`
- 동시 등장 → `animation-delay: calc(var(--index) * 80ms)` 계단식

### 한국어 카피

- AI 상투구 제거: `혁신적인`, `원활한`, `차세대`, `게임 체인저`, `한 차원 높은`
- 번역투 → 자연스러운 한국어. "지금 시작하세요" (O) / "시작을 하세요 지금" (X)
- 경어체 혼용 → 합니다/하세요 중 하나로 고정
- 가짜 반올림 수치 → `50,000+` 대신 `47,200+`, `5.0/5.0` 대신 `4.87/5.0`
- 진부한 예시 이름 `김철수`·`이영희` → `하윤서`, `박도현`, `이서진`

### 코드 품질

- div 남발 → `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`
- `lang="ko"` 누락
- `<title>`, `meta description`, `og:image` 누락
- 이미지에 `loading="lazy"`·`alt` 누락
- 임의 z-index → nav(40), overlay(50), decorative(60)으로 고정

## 3-2. 색 팔레트 재조정 (2026-08-14 3차)

### 측정해서 드러난 문제

색을 눈으로 보지 않고 HSL과 명암비로 재보니 두 가지가 나왔다.

**① 강조색이 대비 기준에 미달했다**

| 색 | 아이보리 배경 대비 | 흰 글씨 대비 | 판정 |
|---|---|---|---|
| `#ee7d53` 코랄(구 accent) | 2.52 | 2.73 | 큰 글씨 기준 3.0도 미달 |
| `#f2a340` 앰버(구 accent-2) | 1.92 | 2.08 | 미달 |
| `#d98a2b` warn | 2.54 | 2.76 | 미달 |

코랄은 `text-lab-accent`로 40여 곳에 쓰이고 주 버튼의 배경이기도 했다.
**화면이 "흐릿하다"고 느껴지던 실제 원인이 이것이다** — 낮은 대비는 눈에
흐릿함으로 읽힌다.

**② 모든 색이 색상환 한 구석에 몰려 있었다**

accent(H16)·accent-2(H33)·warn(H33)·danger(H6)가 전부 H6~H33의 27° 안에
있었다. accent-2와 warn은 색상이 **완전히 같았고**(0°), accent와 danger는
10° 차이였다. 배경(H36)과 본문(H30)까지 주황 계열이라 화면 전체가 한 색으로
보였다.

### 조정 결과

| 토큰 | 이전 | 이후 | 배경 대비 | 흰 글씨 |
|---|---|---|---|---|
| `--color-lab-accent` | `#ee7d53` | `#b8501f` 테라코타 | 4.61 | 4.99 |
| `--color-lab-accent-2` | `#f2a340` 앰버(둘째 강조) | `#e8825c` 밝은 테라코타(연한 면 전용) | — | — |
| `--color-lab-warn` | `#d98a2b` | `#8c6a17` 황금 | 4.62 | 5.01 |
| `--color-lab-danger` | `#d9584a` | `#b23a48` 크림슨 | 5.39 | 5.85 |
| `--color-lab-positive` | `#6a9c5c` | `#367862` 초록 | 4.82 | 5.22 |

조정 후 색상 거리: accent↔danger 26°, accent↔warn 25°, accent↔positive 141°.
전부 20° 이상 떨어져 상태색으로 구분된다. `positive`는 학교 그린과 3° 차이로
**일부러** 같은 계열에 두었다 — 완료 상태를 학교 브랜드 색과 잇는다.

### 강조색을 하나로

- 코랄→앰버 그라디언트를 UI에서 전부 뺐다(버튼·진행바·배지·SVD 막대 6곳).
  17° 차이라 두 색이 섞이는 게 보이지 않고 탁하게만 보였다. 단색이 더 또렷하다.
- `accent-2`는 "둘째 강조색"에서 **같은 색상의 밝은 짝**으로 다시 정의했다.
  지도의 점처럼 연한 면이 필요한 곳에만 쓰고 글자색으로는 쓰지 않는다.

### 죽어 있던 학교 그린을 살렸다

`--color-brand-green`(`#1f5e4c`)은 정의만 되어 있고 **어디서도 쓰이지 않았다**.
테라코타와 144° 떨어져 있어 화면에 축을 하나 더 만들어 준다. 적용한 곳:

- 머리말과 시작 화면의 `LAB` 배지 (기존 코랄 그라디언트 → 학교 그린)
- 로고 글로우
- 배경 얼룩 두 개 중 오른쪽 (왼쪽은 테라코타 — 화면 양 끝의 온도를 다르게)

**원칙은 유지된다.** 장식용 강조색은 여전히 하나(테라코타)다. 그린은 장식이
아니라 브랜드·완료 상태라는 역할을 맡고, 코랄+앰버처럼 같은 자리를 두고
경쟁하지 않는다.

최초 대조는 `index.css`·`index.html`·`ui.tsx` 세 파일만 봤다. 나머지 화면까지
훑어서 아래를 처리했다.

## 4. 이 프로젝트에 적용하지 않는 규칙

원본 스킬은 랜딩 페이지 전용이다. 아래는 이 프로젝트에 **그대로 적용하면 오히려 해가 된다**.

| 스킬 규칙 | 비적용 사유 |
|---|---|
| "인접 섹션은 반드시 다른 레이아웃" | 설문·평가 화면은 **일관성이 정확도를 만든다**. 문항마다 레이아웃이 바뀌면 응답자가 UI를 다시 학습해야 하고 응답 품질이 떨어진다 |
| "3등분 카드 열을 Bento로 교체" | 유형표·군집 카드는 **비교 가능성**이 목적이다. 균일 그리드가 옳다 |
| "CTA는 가장 지배적인 요소" | 전환 유도가 목적인 랜딩과 달리, 여기서는 **문항 내용**이 주인공이다. 다음 버튼이 문항보다 강하면 안 된다 |
| "히어로에 영상 배경" | 부스 현장의 태블릿·모바일 환경에서 대역폭과 배터리를 소모한다. 첫 화면 진입 속도가 우선이다 |
| "단일 standalone HTML로 출력" | React SPA 구조다. 해당 없음 |
| 가짜 지표를 그럴듯한 숫자로 | 이 사이트의 수치는 **실제 계산 결과**다. 꾸미지 않는다 |

원칙: **랜딩 페이지의 목표는 설득이고, 이 사이트의 목표는 측정이다.** 규칙이 충돌하면 측정 쪽을 택한다.

## 5. 앞으로 화면을 추가할 때 확인할 것

새 페이지·컴포넌트를 만들 때 아래만 지키면 톤이 어긋나지 않는다.

1. 색은 `--color-lab-*` 토큰에서만 가져온다. 하드코딩한 hex를 새로 쓰지 않는다
2. 새 강조색을 추가하지 않는다. 장식 강조는 테라코타 하나, 학교 그린은 브랜드·완료 역할로만 쓴다
2-1. 색을 새로 넣거나 바꿀 때는 **눈으로 고르지 말고 먼저 재본다** — 아이보리 배경(`#fbf5ec`) 대비 4.5:1, 흰 글씨를 얹는다면 흰색 대비도 4.5:1. 그리고 기존 의미색과 색상(H)이 20° 이상 떨어지는지 확인한다
3. 그림자는 `var(--shadow-card)` 또는 `var(--shadow-glow-accent)`를 쓴다. `rgba(0,0,0,…)` 직접 작성 금지
4. 등장 애니메이션은 `.lab-enter` / `.lab-stagger`를 쓴다. 새 `@keyframes`를 만들지 않는다
5. 상호작용 요소에는 `active:scale-[0.98]`과 `transition-all`을 붙인다
6. 수치를 표시하면 `font-mono tabular-nums`를 붙인다
7. 카피에서 `혁신적인`·`원활한`·`차세대`를 쓰지 않는다. 경어체는 합니다/하세요로 고정한다
8. 이모지를 **UI 껍데기**(알림·탭·버튼)에 쓰지 않는다. 데이터 항목을 식별하는 이모지(소비대안·유형 아이콘)는 예외다
9. 긴 문단에는 `max-w-[58ch]`(본문)·`max-w-[62ch]`(알림)를 붙인다. 컨테이너 폭을 그대로 쓰면 데스크톱에서 한 줄이 100자를 넘는다
10. 새 z-index를 만들지 않는다. 0 배경 / 1 본문 / 40 고정 막대 / 50 오버레이 네 단계만 쓴다
11. 번호가 매겨진 묶음은 `div`가 아니라 `ol`/`li`로 만든다
12. 작고 흐린 라벨(표 머리글 등)은 SemiBold가 아니라 Medium을 쓴다
