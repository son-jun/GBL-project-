## 2. v1과의 근본적인 차이

| | v1 (기준 데이터셋 방식) | v2 (개인별 방식) |
|---|---|---|
| 입력 단위 | 참가자 N명 × 감정 10개 행렬 | 참가자 1명의 [소비대안 8 × 욕구 6] 행렬 |
| SVD 대상 | 기준 데이터셋 전체 (사전 학습) | 참가자 개인의 평가행렬 (그 자리에서) |
| 중심화 | 기준 평균을 빼는 단계 필요 | 없음 — 개인의 절대 평가 척도를 그대로 사용 |
| K-means 대상 | 기준 데이터셋 참가자들 | 참가자 개인의 소비대안 8개 |
| "모델"이라는 개념 | 있음 (미리 학습, 잠금, 버전관리) | 없음 — 매번 새로 계산되는 "분석 규격"만 있음 |
| 첫 참가자 문제 | 있음 (기준 데이터셋 없으면 결과 불가) | 없음 — 참가자 1명만으로 완결 |
| 데이터 사전 준비 | 필요 (실제 또는 합성) | 불필요 |
| 군집 이름 | 연구자가 사후에 지정 | 참가자마다 규칙 기반 자동 생성 (규칙을 공개) |

이 차이는 `추가 개선 내용.txt`에서 지적한 근본 문제 — "참가자 1명의 벡터는
rank 1이라 SVD가 무의미하다" — 를 해결하기 위한 것이다. 참가자 1명이 스스로
[소비대안 × 욕구] 행렬을 만들면, 그 자체로 rank가 여러 개인 의미 있는 행렬이
된다.

## 4. 데이터 흐름 (참가자 1명, 처음부터 끝까지)

```
참가자 입력
  q  = 현재 감성욕구 6개           (NeedsPage)
  A  = [소비대안8 × 욕구6] 평가행렬  (RatingsPage)
      │
      ▼
validateNeedsVector(q), validateRatingsMatrix(A)   ← 범위·정수·개수 검증
      │
      ▼
computeSvd(A, r)              ── A = U Σ Vᵀ, V의 앞 r열을 잠재축으로
      │                          (SvdPage: 참가자가 설명분산 표를 보고 r 선택)
      ▼
projectMatrixToLatent(A, V_r) ── Z = A·V_r   (소비대안 8개의 잠재좌표)
projectToLatent(q, V_r)       ── q* = q·V_r  (현재 욕구의 잠재좌표)
      │                          (MapPage: 지도 표시)
      ▼
runKMeans(Z, K)                ── 소비대안 8개를 K개 군집으로
nameCluster(needMeans)         ── 각 군집에 즉석 이름 부여
      │
      ▼
distancesToClusters = ‖q* - μk‖ ∀k   ── 가장 가까운 군집 = 잠재수요 유형
distancesToAlternatives             ── 그 군집 안에서 가장 가까운 대안 = 세부 잠재수요
      │                          (ClusterPage: 계산 실행 + 저장)
      ▼
participantRepository.save(record)
      │
      ▼
결과 화면 (ResultPage) — 거리 기반 탐색적 해석 제시
```

이 전체가 [`runPersonalAnalysis`](../src/lib/math/inference.ts) 함수 하나로
캡슐화되어 있고, [`ClusterPage`](../src/pages/ClusterPage.tsx)에서 호출된다.
호출에 필요한 것은 참가자의 입력(q, A)과 옵션(r, K)뿐이며, 외부 데이터에
의존하지 않는다.

## 5. 재현성

"같은 입력 + 같은 옵션 → 같은 결과"를 보장하는 장치는 v1과 동일한 원리다:

| 장치 | 위치 |
|---|---|
| 시드 고정 PRNG | `math/random.ts`, `ANALYSIS_SPEC.randomSeed` |
| SVD 고유벡터 부호 규약 | `math/svd.ts` (절댓값 최대 성분을 양수로 고정) |
| 군집 번호 정규화 | `math/kmeans.ts` (중심 좌표 오름차순으로 재배열) |
| 동률 처리 규칙 | `math/inference.ts` (거리가 같으면 번호가 작은 쪽) |

단위 테스트: `같은 입력 + 같은 옵션이면 항상 같은 결과다` — `runPersonalAnalysis`를 두 번 호출한 결과의 JSON 문자열이 완전히 일치하는지 검증한다.

## 7. 설계 판단 기록

### 왜 중심화를 하지 않는가

v1은 "사람마다 채점 습관이 다르다"는 이유로 기준 집단 평균을 뺐다. v2의
평가행렬 A는 성격이 다르다 — 각 셀은 "이 소비가 이 욕구를 얼마나 채우는가"에
대한 그 사람만의 **상대적 판단**이지, 여러 사람이 채점 습관 차이 없이 비교되어야
하는 절대 점수가 아니다. `추가 개선 내용.txt`의 11단계 흐름에도 중심화
단계가 없다. 그래서 원본 평가값을 그대로 SVD에 사용한다.

### 왜 소비대안 군집 이름을 시스템이 자동으로 짓는가

원본 요청서 §23-4는 "K-means가 이름을 지은 것처럼 보이면 안 된다"고 못박았다.
이 원칙은 **하나의 고정된 기준 데이터셋**을 전제로 한 것이었다 — 연구자가
시간을 들여 그 군집을 해석할 여유가 있는 상황이다.

v2는 군집이 매 참가자마다 실시간으로 새로 만들어진다. 부스에서 수십 명이
각자 다른 소비대안 조합의 군집을 받는데 연구자가 매번 이름을 붙일 수 없다.
그래서 이름 짓기 규칙 자체를 코드로 명시하고 ([`clusterNaming.ts`](../src/lib/math/clusterNaming.ts)), 이 규칙이 "숨겨진 진실의 과학적 발견"이 아니라
"참가자가 스스로 입력한 숫자의 요약"임을 결과 화면에서 투명하게 설명한다
(`CLUSTER_NAMING_EXPLANATION`). 원칙의 정신(시스템이 임의로 확정 판단을
내리는 것처럼 보이지 않게 하기)은 유지하되, 구현 방식을 새 구조에 맞게
바꾼 것이다.

### 왜 소비대안이 8개, 감성욕구가 6개인가

`추가 개선 내용.txt`가 명시적으로 권장한 값이다: "소비대안이 6개뿐이라면
K-means를 엄밀한 연구분석으로 강조하기에는 관측점이 적습니다... 8~10개 정도로
늘리는 것을 권합니다." 8×6 크기는 SVD가 2~3개의 뚜렷한 잠재축을 찾기에
충분하면서도, 부스 활동으로 감당할 수 있는 입력량(48칸)이다.

### Windows 관련 주의사항 (실제로 부딪힌 것)

Node 22 + Windows(OneDrive 동기화 경로)에서 Vite의 gzip 크기 계산 단계가
네이티브 크래시를 일으키는 것을 확인해 `build.reportCompressedSize: false`로
비활성화했다. 번들 결과 자체에는 영향이 없다.
